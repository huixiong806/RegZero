# 关卡编写规范

> 本文档是**纯技术参考手册**，用于指导人类作者、AI Agent 或未来自制关卡玩家如何配置并验证一个完整关卡。
> 关于“如何把关卡设计得让零基础玩家玩得顺手”，请先阅读 [`关卡设计规范.md`](关卡设计规范.md)；引擎架构见 [`架构.md`](架构.md)。

---

## 1. 单关目录结构（`content/levels/cN_M/`）

每个关卡独立占用 `content/levels/` 下的一个目录。命名约定：`N` 为章号，`M` 为关号，**不补零**；支线挑战后缀小写 `s`（如 `c1_4s` 对应关卡 ID `"1-4S"`）。

| 文件 | 必需 | 作用 |
|------|:---:|------|
| `meta.json` | ✅ | 元信息、前置依赖、`ui` 展示开关、`briefing`、沙盘配置、`editor` 约束、3 级提示 |
| `lesson.md` | ✅ | 本关规则与任务说明（Markdown） |
| `starter.s` 或 `starter.c` | 第 1~2 章 | 编辑器初始代码与只读首尾行脚手架 |
| `tests.json` | ✅ | 测例列表、指令白名单、禁用寄存器、判定类型 |
| `solution.s` / `solution.c` / 参考工程 | ✅ | **参考解**（`selfcheck` 自检用它验证关卡必定可解） |

## 2. `meta.json` 字段参考

### 2.1 完整示例

```json
{
  "id": "1-6",
  "chapter": 1,
  "order": 6,
  "kind": "lesson",
  "title": "打破直线：PC、标签与条件跳转（blt / j）",
  "mode": "online",
  "allowLocalFile": true,
  "language": "asm",
  "prerequisites": ["1-5"],
  "concepts": ["pc", "label", "blt", "bge", "j"],
  "ui": {
    "immediatePort": true,
    "jumpRail": true,
    "debugControls": true
  },
  "goalSummary": {
    "before": "t0 与 t1 中存有两个整数",
    "after": "将 t0 与 t1 中的较大值存入 t2"
  },
  "briefing": [
    {
      "tag": "新概念",
      "text": "CPU 靠 **PC（程序计数器）** 决定下一条执行哪一行指令，默认总是从上往下顺序执行。"
    },
    {
      "tag": "先找 Bug",
      "text": "右边编辑器里已经写好了一段**带 Bug 的代码**。先直接点「运行并提交」，盯着左边动画看看哪里出了问题！"
    }
  ],
  "sandbox": {
    "type": "manual-cpu",
    "focusWarmupFirst": false,
    "modules": ["regs", "alu"],
    "recordToAsm": false,
    "focusRegs": ["t0", "t1", "t2"],
    "regRoles": {
      "t0": "输入 A",
      "t1": "输入 B",
      "t2": "较大值"
    },
    "aluOps": ["+"],
    "warmupPuzzle": {
      "prompt": "直接点右侧「运行并提交」，观察为何结果被覆盖，再补上跳转指令。",
      "initial": { "regs": { "t0": 12, "t1": 5, "t2": 0 } },
      "goal": { "regs": { "t2": 12 } }
    }
  },
  "editor": {
    "readonlyPrefix": 1,
    "readonlySuffix": 1
  },
  "hints": [
    { "level": 1, "type": "diagram", "content": "先判断 t0 < t1 时跳去执行 mv t2, t1；否则顺序执行后用 j done 跳过另一条路线。" },
    { "level": 2, "type": "steps", "content": "在 mv t2, t0 下方补上 j done。" },
    { "level": 3, "type": "snippet", "content": "blt t0, t1, use_t1\nmv  t2, t0\nj   done\nuse_t1:\nmv  t2, t1\ndone:" }
  ],
  "wikiRefs": ["rv32-branch"]
}
```

### 2.2 核心元字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | 关卡 ID（如 `"1-1"`、`"1-4S"`），必须与目录名、`tests.json` 中的 `level` 一致 |
| `chapter` | `number` | 所属章节号（`1`~`7`） |
| `order` | `number` | 章内排序键，支持小数（如 `4.5` 表示挂在 `1-4` 旁的支线） |
| `kind` | `"lesson" \| "practice" \| "challenge"` | 概念关 / 巩固关 / 不阻塞主线的支线挑战 |
| `mode` | `"online" \| "local-project"` | 第 1~2 章默认 `"online"`；第 4~7 章 C 编译器工程关为 `"local-project"` |
| `allowLocalFile` | `boolean` | 是否允许在 Playground 切换为本地单文件监听模式（第 1~2 章通常为 `true`） |
| `language` | `"asm" \| "c" \| "draw-script"` | 本关编程语言 |
| `prerequisites` | `string[]` | DAG 前置关卡 ID 列表（空数组表示默认解锁） |
| `parInstructions` | `number?` | 可选，支线关的最优静态指令条数挑战目标（参考解必须满足 `<= parInstructions`） |
| `concepts` | `string[]` | 本关引入的概念标签，用于驱动 `content/wiki/*.json` 的图鉴解锁与 `NEW` 标记 |
| `briefing` | `{ tag, text }[]` | 首次进关弹出的多页引导卡片（支持 Markdown 行内粗体与反引号） |
| `wikiRefs` | `string[]` | 本关关联的图鉴词条 `topic` 列表（对应 `content/wiki/<topic>.json`） |

### 2.3 单关独立界面开关（`ui`）

每关的 `ui` 对象**完全独立生效，不从前置关卡继承**；所有字段均可选，缺省一律为 `false`：

| `ui` 字段 | 默认 | 为 `true` 时的效果 |
|-----------|------|-------------------|
| `immediatePort` | `false` | CPU 舞台展示右侧「立即数」端口与 Y 型汇流总线 |
| `jumpRail` | `false` | CPU 舞台展示右侧「跳转 / 循环 PC 回流轨」 |
| `memoryStage` | `false` | CPU 舞台展示「访存」模块，且工作台展示内存监视器 |
| `pipelineStages` | `false` | CPU 舞台展示顶部 5 阶段微架构状态灯带及「取指/译码/执行/访存/写回」术语标签 |
| `debugControls` | `false` | 工作台顶部展示测例选择、试运行与单步调试按钮 |
| `regXName` | `false` | 寄存器卡片右上角展示底层硬件编号（`x0–x31`） |
| `allRegsToggle` | `false` | 寄存器盒展示「32 格」全部寄存器展开切换按钮 |
| `hexToggle` | `false` | 寄存器面板展示「DEC / HEX」进制切换按钮 |
| `untrackedRegs` | `false` | 寄存器面板展示未在 `focusRegs` 内但非零的系统寄存器（如 `sp=0xF000`） |
| `ecallSuffix` | `false` | 编辑器显示末尾只读的 `ecall` 行（为 `false` 时自动隐藏并在运行时无损拼回） |

### 2.4 四套沙盘配置（`sandbox.type`）

| `sandbox.type` | 适用章节 | 常用配置字段 |
|---------------|---------|-------------|
| `manual-cpu` | 第 1 章 | `modules`（`regs`/`constants`/`alu`）、`focusWarmupFirst`、`recordToAsm`（启用中文语义记录 + 抽象语法骨架）、`focusRegs`、`regRoles`、`constantCards`、`aluOps`、`warmupPuzzle`（含 `guards` 如 `warnOverwriteLostValue`） |
| `memory-canvas` | 第 2~3 章 | 预留：`focusVars`、`showAsmDiff`、`predictQuestions` |
| `lexer-ast-lab` | 第 4~5 章前端 | 预留：`interactiveMode: "lexer" \| "ast"`、`sampleInput` |
| `pipeline-stage` | 第 4~7 章后端 | 预留：`activeStages`、`outputView: "draw-canvas" \| "riscv-monitor"` |

### 2.5 编辑器约束（`editor`）

- `readonlyPrefix`: 顶部只读行数（如 `1` 锁定首行任务注释）。
- `readonlySuffix`: 底部只读行数（如 `1` 锁定末尾 `ecall`；配合 `ui.ecallSuffix: false` 对新手隐形）。
- `highlight`: 可选，高亮提示的行号数组（1-based）。
- `suggested`: 可选，行号 → 占位提示文案映射（注意不要剧透完整答案）。
- 约束：`readonlyPrefix + readonlySuffix` 必须严格小于 `starter` 总行数，且行号不得越界。

## 3. `tests.json` 测试配置参考

### 3.1 第 1~2 章静态/输出关（`static` / `output`）

```json
{
  "level": "1-6",
  "language": "asm",
  "availableOps": ["add", "addi", "sub", "mv", "blt", "bge", "j", "ecall"],
  "forbiddenRegs": [],
  "maxInstructions": 1000,
  "goal": {
    "type": "static",
    "tests": [
      {
        "name": "12 与 5：较大值为 12",
        "initial": { "regs": { "t0": 12, "t1": 5 } },
        "expected": { "regs": { "t2": 12 } }
      }
    ]
  }
}
```

- 寄存器名支持 ABI 名（`t0`、`a0` 等）或硬件编号（`x5`、`x10` 等）。
- 函数调用模式可写 `"call": { "fn": "solve", "args": [3, 7] }` + `"expected": { "ret": 10 }`（第 2 章主力，引导桩位于 `0x0800`）。
- 字符串内存写法：`{"string": "abc"}`；输出文本比对会自动规范化首尾空白与空行。

### 3.2 绘图脚本关（`draw_sim`）

```json
{
  "level": "4-7",
  "language": "draw-script",
  "maxInstructions": 20000,
  "goal": {
    "type": "draw_sim",
    "tests": [
      {
        "name": "绘制四段递增螺旋线",
        "input": { "text": "let i = 0; pen(1); while (i < 4) { move(20 + i * 10); turn(90); i = i + 1; }" },
        "expectedSegments": [
          [0, 0, 20, 0],
          [20, 0, 20, 30],
          [20, 30, -20, 30],
          [-20, 30, -20, -20]
        ]
      }
    ]
  }
}
```

### 3.3 编译器代码生成关（`compile_and_run`）

```json
{
  "level": "5-9",
  "language": "c",
  "maxInstructions": 50000,
  "goal": {
    "type": "compile_and_run",
    "tests": [
      {
        "name": "递归计算 5 的阶乘",
        "program": "int fact(int n) { if (n <= 1) return 1; return n * fact(n - 1); } int main() { return fact(5); }",
        "expected": { "exitCode": 120 }
      }
    ]
  }
}
```

## 4. RISC-V 引擎注意事项（写汇编关卡与参考解必查）

1. **`a7` 是 `x17`，不是 `x11`**：系统调用号写错到 `x11` 会导致 `a7 == 0`，每次 `ecall` 直接退出程序。
2. **不要把 `x1` 当临时寄存器**：`x1` 是 `ra`，`jal`/`call` 会覆盖它；临时值用 `t0`–`t6`。
3. **跨 `jal` 保存的值放 `s0`–`s11` 或压栈**：`t0`–`t6`、`a0`–`a7` 随时可能被子函数改写；`ecall` 本身只写 `a0`。
4. **MMIO 输入端口读宽度**：`0xF0000004` 上无论用 `lw`/`lh`/`lbu`/`lb`，都只消费 1 个字符（空返回 0）。
5. **`.word` 不自动对齐**：`.asciz`/`.byte` 后接 `.word` 必须显式写 `.align 4`，否则触发未对齐访存错误。
6. **“空输出”测例必须加 `expected.memory`**：输出规范化会丢空行，单靠 `output.text: ""` 会放过空骨架。

## 5. 本地校验与构建命令

新增或修改任何关卡文件（`meta.json` / `lesson.md` / `starter.*` / `tests.json` / `solution.*` / `content/wiki/*.json`）后，按顺序运行：

```bash
# 1. 校验全部关卡配置、Wiki 引用、只读行范围与参考解可解性
cargo test -p regzero-core selfcheck -- --nocapture

# 2. 重新编译内嵌了最新关卡内容的 WASM 包并校验前端构建
cd web && npm run wasm:build && npm run typecheck && npm run build
```

> 若正在运行 `vite dev` 预览，重编 `wasm-pkg` 后需清理 `web/node_modules/.vite` 并强刷浏览器（`Ctrl+Shift+R`），避免加载旧 `.wasm` 缓存。
