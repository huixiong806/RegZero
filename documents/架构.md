# 架构设计（网页化 + 强交互沙盘 + 本地项目桥接）

> 本文定义 `no_story` 分支的**已拍板系统架构**，明确前端技术栈、双部署形态、4 套强游戏化沙盘的数据驱动架构、现有 Rust 核心复用清单，以及 `nmc-wasm` / `nmc-bridge` 协议。
> 原 `Tauri 2 + mdBook` 方案已废弃，迁移路径见 §7。

---

## 1. 总体架构：Web SPA + 双执行后端 + 双部署形态

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  表示层  web/  (Vite + TypeScript + React + Tailwind CSS + CodeMirror 6)      │
│   ├─ 关卡地图 (Skill Tree)                                                    │
│   ├─ 4 套强游戏化可玩沙盘 (手动 CPU / 内存画布 / 词法AST台 / 产线与DrawVM)      │
│   ├─ 独立 Playground (在线编辑 / 本地单文件 / 本地 C 工程 三模式切换)           │
│   └─ 侧滑概念图鉴 Wiki                                                         │
└────────────────────────┬─────────────────────────────────┬───────────────────┘
                         │ 统一 EngineClient 接口           │
            ┌────────────▼────────────┐       ┌────────────▼────────────┐
            │  模式 A：浏览器内置引擎   │       │  模式 B：本地桥接客户端  │
            │  crates/nmc-wasm (WASM) │       │  HTTP + WebSocket       │
            │  Web Worker 内运行      │       │  127.0.0.1:17320        │
            └────────────┬────────────┘       └────────────┬────────────┘
                         │                                 │
                         │                    ┌────────────▼──────────────────────┐
                         │                    │  crates/nmc-bridge (本地轻量服务)   │
                         │                    │   ├─ 可选托管 web/dist 静态页面     │
                         │                    │   ├─ 启动体检 (gcc/clang/make 指引) │
                         │                    │   ├─ 单文件监听 (第 1~2 章 .s/.c)   │
                         │                    │   ├─ C 工程识别 (nmc.project.json) │
                         │                    │   ├─ 构建 + 超时沙箱运行玩家编译器   │
                         │                    │   └─ 本地存档无损同步               │
                         │                    └────────────┬──────────────────────┘
                         │                                 │
                         └────────────────┬────────────────┘
                                          ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│  核心领域与执行层  crates/ （几乎 100% 复用现有 Rust 代码）                      │
│   ├─ neomagic-core      关卡加载 / 运行器 / DrawVM / 判定器 / 存档 / 自检       │
│   ├─ starlang           C 子集 → RISC-V 汇编（第 2 章执行与三联对照）           │
│   ├─ riscv-assembler    两遍扫描汇编器（文本 → 机器码 + 行号映射）               │
│   └─ riscv-simulator    RV32IM 模拟器 + MMIO + 历史回溯（单步/倒退）             │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 双部署形态（同时支持）

1. **线上静态部署**：`web/dist` 部署在 GitHub Pages / Gitee Pages 等静态托管平台。零基础玩家打开网址即用 `nmc-wasm` 零安装开玩第 1~2 章；进入第 3 章后在本机启动 `nmc-bridge`，网页自动通过 `127.0.0.1:17320`（配置好 localhost CORS）连上本地工程。
2. **本地一体托管**：`nmc-bridge` 内置静态文件服务，玩家本地运行一条命令并打开 `http://127.0.0.1:17320` 即可离线游玩全部章节，无跨域问题。

## 3. 新增后端层：`nmc-wasm` 与 `nmc-bridge`

### 3.1 `crates/nmc-wasm`（浏览器内置引擎）

- 通过 `wasm-bindgen` 暴露 `run_code`、`submit_code`、`debug_start`、`debug_step`、`debug_step_back`、`debug_continue`、`debug_reset`、`compile_starlang_with_map`、`run_draw_vm`。
- 运行在浏览器 **Web Worker** 中，防止玩家代码死循环阻塞动画帧率。

### 3.2 `crates/nmc-bridge`（本地桥接服务）

基于 `axum` + `tokio` + `notify`，默认仅监听 `127.0.0.1:17320`（拒绝外部 IP 访问）。核心职责：

1. **启动环境体检**：启动时自动探测本机 `gcc` / `clang` / `make` 版本，向网页报告就绪状态；若缺失编译器，返回对应操作系统（Windows / macOS / Linux）的极简安装指引，不内置臃肿工具链，但在项目配置中支持自定义编译器路径。
2. **本地单文件监听模式（第 1~2 章可选）**：绑定本地某个目录或单个 `.s`/`.c` 文件；玩家在 VS Code 里按 `Ctrl+S`，Bridge 自动读取最新文件内容并通过 WebSocket 推送给网页 Playground，触发即时运行与沙盘动画。
3. **本地 C 工程模式（第 3~6 章主力）**：
   - 识别项目根目录的 `nmc.project.json`；
   - 监听 `src/`、`include/`、`Makefile` 文件变更（300ms 防抖），支持 Auto-Watch 保存即自动构建与跑测例；
   - 执行构建命令并流式推送编译日志；
   - 沙箱超时运行玩家编译出的可执行文件（默认单测例 2 秒上限 + 输出体积上限），捕获非零退出与崩溃信号（如段错误）翻译为人话提示；
   - 将产物送入 `DrawVM`（第 3 章）或 `riscv-assembler` + `riscv-simulator`（第 4~6 章）判定，并支持将任意失败测例装入调试会话供网页端单步/倒退回放。
4. **静态网页托管（可选）**：检测到本地前端产物目录时自动托管于 `http://127.0.0.1:17320`。
5. **进度同步**：与网页端无损合并同步 `~/.neomagiccompiler/user_progress.json`。

## 4. 本地项目规范与通信协议

### 4.1 项目识别文件：`nmc.project.json`

```json
{
  "schemaVersion": 1,
  "name": "my-c-compiler",
  "track": "chapter4",
  "mode": "c-project",
  "build": {
    "command": "gcc -Wall -Wextra -g src/*.c -o build/nmcc",
    "workingDir": ".",
    "timeoutMs": 15000
  },
  "executable": "build/nmcc",
  "watch": ["src", "include", "Makefile"]
}
```

对于第 1~2 章的本地单文件模式，可无需手写配置，直接启动 `nmc-bridge --watch-file ./level1_5.s`，或在网页端选择目标文件即可。

### 4.2 玩家编译器 CLI 契约

- **输入**：从 `stdin` 读取待编译的源程序文本。
- **正常输出**：向 `stdout` 打印目标产物（Token 流 / AST 文本 / `DrawVM` 指令流 / RISC-V 汇编文本），退出码 `0`。
- **错误输出**：语法或语义错误写入 `stderr`，返回非 `0` 退出码。
- **阶段参数（同一本地 C 工程贯穿多章的关键）**：支持 `--stage <lex|parse|sema|codegen>`，使同一个本地项目既能通过词法/语法关，也能跑通端到端代码生成关。

### 4.3 `nmc-bridge` HTTP + WebSocket 接口

所有 JSON 字段统一 `camelCase`，由共享契约测试约束前后端一致：

| 类别 | 接口 / 事件 | 说明 |
|------|-----------|------|
| 体检 | `GET /api/health` | 返回 Bridge 版本、本机 `gcc`/`clang`/`make` 检测结果、当前绑定模式与项目摘要 |
| 绑定 | `POST /api/project/select` | 切换本地 C 工程目录或本地单文件路径 |
| 脚手架 | `POST /api/project/init` | 在指定目录生成第 3/4 章 C 工程模板 |
| 构建 | `POST /api/project/build` | 触发本地 C 工程编译，返回成功状态与编译日志 |
| 运行 | `POST /api/level/:id/run` | 用默认测例跑一次（不计分，返回产物与快照/绘图轨迹） |
| 提交 | `POST /api/level/:id/submit` | 跑完该关全部测例（可先自动构建），返回 `SubmitDto`（含各测例 Diff 与失败现场） |
| 调试 | `POST /api/debug/start` / `step` / `step-back` / `continue` / `reset` / `quit` | 对指定测例（`caseIndex`）进行单步/倒退调试 |
| 实时流 | `WS /ws` | 推送 `file.changed`、`project.changed`、`build.log`、`test.progress`、`bridge.status` |

## 5. Web 前端、强交互沙盘与独立 Playground 架构（`web/`）

### 5.1 路由结构

| 路由 | 页面 | 核心能力 |
|------|------|---------|
| `/` | 关卡地图与技能树 | 6 章节点图、进度条、Bridge 状态灯、快捷进入独立 Playground |
| `/level/:id` | 关卡学习页 | 顶部 Before/After 目标卡；左栏：可玩沙盘引导 + 精简说明 + 3 级 Hint；右栏：嵌入式 Playground |
| `/playground` | **独立 Playground** | 顶栏切换 `在线编辑 / 本地单文件 / 本地 C 工程` + 测例选择器 + Watch 开关；主区统一承载代码/项目面板、实时沙盘画布、调试器与测例 Diff |
| `/wiki/:topic` | 概念图鉴 | 可交互速查卡：RV32IM 指令、C 语法、数据结构模板、`DrawVM` 指令集 |

### 5.2 四套数据驱动强游戏化沙盘组件（`web/src/sandboxes/`）

| 组件目录 | 核心交互能力 | 数据来源 |
|---------|------------|---------|
| `manual-cpu/` | 竖向 5 阶段单周期 CPU 数据通路舞台（`取指 → 译码 → 执行 → 访存 → 写回` + 左右回流总线 + 1~32 自适应寄存器堆与独立常量口）：静止时可手动拖放试算，运行/单步时由 `ExecutedOpDto` 按 `1x/2x/4x` 节拍依次演完 5 个阶段（`mv` 真实走 `addi +0` 统一通路） | 关卡 `meta.json` + 模拟器 `StepPayload.executed` |
| `memory-canvas/` | 2D 内存阵列、可拖拽指针箭头、结构体展开、链表/树连线、预测点击交互 + C↔汇编三联高亮 | `starlang` 行映射 + 模拟器内存快照 |
| `lexer-ast-lab/` | 字符传送带手动切词贴标签 + Token 卡片拖拽拼 AST 树 + 后序遍历指令吐出动画 | 关卡 `meta.json` 互动脚本 + 玩家编译器产出的 Token/AST |
| `pipeline-stage/` | 顶部通电流水线状态条 + 底部可切换视图（**`DrawVM` 实时 SVG/Canvas 绘图画布** / RISC-V 调试监视器 / 输出终端） | `DrawVM` 绘图轨迹数组 / `MachineSnapshot` / `SubmitDto` |

### 5.3 统一引擎抽象（`EngineClient`）

前端 UI 组件不直接依赖具体后端，全部通过 `EngineClient` 接口交互：
- `OnlineWasmClient`（Web Worker 中的 `nmc-wasm`）
- `LocalBridgeClient`（`127.0.0.1:17320` HTTP + WebSocket）

切换「在线编辑 / 本地单文件 / 本地 C 工程」只需替换当前 `EngineClient` 与代码源，**四套沙盘、单步/倒退调试器与 Diff 面板 100% 复用**。

### 5.4 渐进式信息披露（Progressive Disclosure）需求与架构规范

> 面向零基础玩家的核心产品约束：**禁止在尚未教学前将未学术语、硬件编号或系统默认寄存器直接暴露给玩家**。即使未来整体重写，也必须从第一天遵守本节规范。

1. **单一真相源（`concepts[]`）**：
   - 每个关卡在 `content/levels/cN_M/meta.json` 声明 `concepts: string[]`；严禁在任何前端或后端代码中按 `levelId` 硬编码展示条件。
   - 纯函数领域层 `web/src/domain/knowledge.ts` 汇总玩家「所有已通关 + 已解锁 + 当前进入关卡」的 `concepts`，派生出 `KnowledgeState { revealAll, knownConcepts, ui }`；仅在开启「自由探索」或处于独立 Playground 自由沙盒模式时置 `revealAll = true`。
   - `AppShell` 集中维护一份 `levels` 与 `knowledge` 上下文，避免各页面重复拉取关卡列表导致状态分裂。

2. **渐进生长的结构化概念图鉴（`content/wiki/*.json`）**：
   - 词条采用强类型 JSON Schema（`neomagic-core::dto::WikiEntry`），包含词条级 `unlockAny`、分段级 `unlockAny`、表格列级 `unlockAny` 与表格行级 `unlockAny`。
   - **未解锁内容完全隐藏**（不展示剧透标题或空表）；随通关推进，速查表自动逐行/逐列生长（例如 1-1 仅见 `t0–t2` 与 `add`，1-2 自动补入 `zero` 与 `addi`），并对本关新引入的知识点标记 `NEW`。
   - `neomagic-core` 一致性测试强制校验全部 Wiki JSON 可解析、列引用合法且无废弃剧情词。

3. **单关独立的界面与 CPU 舞台配置（`meta.json` 的 `ui` 字段，零跨关继承）**：
   - 每个关卡在 `meta.json` 中通过 `ui: LevelUiConfig` **完全独立**声明本关要显示哪些界面与 CPU 硬件部件（缺省项一律为 `false`，经 `resolveLevelUiDisclosure(level.meta.ui)` 直接映射，**绝不从前置关卡继承**，便于单独微调关卡以及未来玩家自定义关卡）：

| `meta.ui` 字段 | 映射开关 | 为 `false` 时的零基础表现 |
|---------------|---------|--------------------------|
| `immediatePort` | `showImmediatePort` | 隐藏右侧「立即数」端口，总线退化为寄存器双直线通道 |
| `jumpRail` | `showJumpRail` | 隐藏右侧「跳转 / 循环 PC 回流轨」 |
| `memoryStage` | `showMemoryPanel` | 隐藏内存监视器，且 CPU 沙盘中**彻底不渲染「访存」阶段模块** |
| `pipelineStages` | `showPipelineStages` | 隐藏顶部「取指/译码/执行/访存/写回」微架构灯带及术语标签，只保留流畅物理数据流 |
| `debugControls` | `showDebugControls` | 工具栏仅保留单一主按钮「运行并提交」，隐藏测例下拉、试运行与单步调试按钮 |
| `regXName` | `showRegXName` | 寄存器卡片隐藏 `x0–x31` 硬件编号，优先展示 `regRoles` 中文角色；失败 Diff 中 `xN` 自动转 ABI 名 |
| `allRegsToggle` | `showAllRegsToggle` | 隐藏 `32 格` 全部寄存器展开按钮 |
| `hexToggle` | `showHexToggle` | 隐藏 `DEC/HEX` 进制切换按钮，固定十进制 |
| `untrackedRegs` | `showUntrackedNonZeroRegs` | 仅展示 `focusRegs ∪ changedRegs`，不把 `sp=0xF000` 泄露到早期关卡 |
| `ecallSuffix` | `showEcallSuffix` | 编辑器自动隐藏末尾只读 `ecall` 行（`splitHiddenReadonlySuffix`），提交与运行时无损拼回 |

4. **沙盘交互、防抄袭与两段式聚焦约束**：
   - 第 1 章运算台不出现 `ALU` / `ASM` / `IN` / `OUT` / `IMM` / `WASM` 等未经教学的英文缩写，统一使用直观中文标签（`输入` / `存入` / `常量` / `操作记录`）。
   - `输入` 与 `存入` 采用一致的拖放/顺序点击交互模型（支持寄存器卡片拖入 `存入`，也支持双输入就绪后将 `存入` 反向拖到目标寄存器卡片立即写入）。
   - **防无脑抄袭闭环**：沙盘不直接打印可执行答案汇编，仅回显中文操作语义 + **同色指令语法骨架**（如 `add` `[存入]`(绿), `[输入 1]`(青), `[输入 2]`(青)）；编辑器不放完整答案占位符；写反源/目的顺序时仅展示清晰测例 Diff，不额外保姆式剧透，保留必要思考台阶以衔接后续章节难度。
   - **目标常驻可见 + 柔化两段式聚焦**：顶部通栏常驻高亮「本关目标（初始 → 目标）」卡片；未通关时先突出「1 先动手试算」，右侧代码区柔化降噪且隐藏运行前的空结果面板；点击「去写指令 →」或直接点击右侧时切换至「2 写下指令并提交」焦点，不强制锁死老玩家。
   - **首次进场多页微引导 + 飞入「规则」按钮收起动效**：每关 `meta.json` 可声明 `briefing: BriefingSlide[]`（每页 1~2 句口语化新概念/目标说明）。首次进入未通关关卡时自动弹出，支持键盘翻页与跳过；关闭时以真实坐标缩放飞入右上角「规则」按钮并点亮按钮脉冲，自然建立“详细书面规则与重播入口在「规则」按钮内”的心智映射。

### 5.5 多语言国际化（i18n）扩展规范

> 当前阶段默认以简体中文为唯一上线语言，但所有 UI 文案与内容文件均预留低成本翻译扩展位，严禁把文本不可逆地写死在业务逻辑里：

1. **前端 UI 词典层（`web/src/i18n/`）**：
   - `zh-CN.ts` 作为强类型基准词典（`MessageCatalog`），通过 `t(key, params?)` 访问并支持 `{var}` 占位插值；
   - 新增翻译语言（如 `en-US.ts`）只需实现同类型 `MessageCatalog` 并在 `index.ts` 注册，TypeScript 编译期自动检查有无漏翻词条。
2. **关卡与图鉴内容层（`content/` 零破坏覆盖约定）**：
   - 默认中文内容直接写在 `content/levels/cN_M/meta.json`、`lesson.md` 与 `content/wiki/<topic>.json`；
   - 后续社区/维护者新增语言（如 `en`）时，仅需同目录放置语言覆盖文件 `content/levels/cN_M/i18n/en.json`（覆盖 `title`/`goalSummary`/`briefing`/`hints`/`regRoles`）+ `lesson.en.md`，以及 `content/wiki/i18n/en/<topic>.json`，后端按「目标语言覆盖 → 回退默认中文」合并，翻译贡献者无需改动任何 Rust 或 React 代码。
