# 术语表

本文档统一定义 RegZero（零号寄存器）跨文档使用的核心术语与标识符约定。
全面采用准确、可迁移的真实计算机术语。

---

## 一、核心教学与视觉隐喻（替代旧魔法词汇）

| 正式计算机术语 | 教学视觉隐喻（面向零基础） | 说明 |
|--------------|------------------------|------|
| CPU / 处理器 | 指令执行台（含 ALU 计算器） | 不再称“魔导核心 / 魔导引擎” |
| 寄存器（Register） | CPU 桌面上的 32 个编号数字槽 | 统一使用 `x0`–`x31` 与标准 ABI 名（`sp`/`ra`/`a0` 等） |
| 内存（Memory / RAM） | 按地址编号排列的储物柜阵列 | 不再称“记忆晶阵” |
| 栈（Stack） | 顶部压入/弹出的积木柱 | `sp` 指向栈顶，向下增长 |
| RISC-V 汇编 | 机器指令清单（RV32IM） | 不再称“星之语 / 星之印” |
| C 子集 | 高级语言（第 2 章学习 / 第 4~5 章源语言） | 不再称“星咒”；Rust crate 名 `starlang` 因历史原因保留 |
| 周期数（Ticks / Cycles） | 执行步数 / 性能开销 | 不再称“魔力消耗” |

## 二、目标机器与语言

| 术语 | 标识 / 所属模块 | 说明 |
|------|---------------|------|
| **RV32IM 模拟器** | `crates/riscv-simulator` | 完整 RV32IM 执行引擎，含 MMIO 与环形历史回溯 |
| **RISC-V 汇编器** | `crates/riscv-assembler` | 两遍扫描汇编器，产出机器码与 `source_map`（地址↔行号） |
| **`starlang`** | `crates/starlang` | 第 2 章内置 C 子集 → RISC-V 汇编编译器（支持 C↔汇编对照高亮） |
| **`DrawVM`** | `crates/regzero-core`（规划新增） | 第 3 章使用的 15 指令极简栈式绘图虚拟机（算术/比较/变量槽/跳转 + `MOVE`/`TURN`/`PEN`/`COLOR`） |
| **C 核心子集** | 第 4 章编译器源语言 | 纯核心子集：`int`、算术/比较/逻辑表达式、局部/全局变量、`if/else`、`while`、函数与递归（单文件汇编输出） |
| **C 扩展子集** | 第 5 章编译器源语言 | 在核心子集上扩展：数组、指针、`char`/字符串、`struct`、位运算、`for`/`break`/`continue`、内建 I/O |

## 三、强游戏化交互沙盘与前端模块

| 术语 | 标识 / 路径 | 说明 |
|------|-----------|------|
| **独立 Playground** | 路由 `/playground` | 全游戏共享的核心工作台，支持「在线编辑 / 本地单文件 / 本地 C 工程」三模式切换，可自由实验或挂载任意关卡测例 |
| **沙盘 1：手动当 CPU** | `manual-cpu` | 第 1 章交互沙盘：拖拽数字进寄存器/ALU/内存/栈，自动将手工步骤录制成等价 RISC-V 汇编 |
| **沙盘 2：内存画布** | `memory-canvas` | 第 2 章交互沙盘：2D 内存网格、可拖拽指针箭头、结构体/链表/树可视化、预测点击题 + C↔汇编三联高亮 |
| **沙盘 3：词法与 AST 台** | `lexer-ast-lab` | 第 3~4 章前端沙盘：字符传送带手动切词贴 Token 标签 + Token 卡片拖拽拼装 AST 树并播放后序吐码 |
| **沙盘 4：实时产线** | `pipeline-stage` | 第 3~6 章后端沙盘：顶部通电式编译器流水线 + 底部 `DrawVM` 绘图画布或 RISC-V 执行监视器 |
| **概念图鉴（Wiki）** | `/wiki/:topic`、`content/wiki/` | 侧滑按需查阅的交互速查表与参考数据结构模板 |

## 四、网页引擎与本地桥接

| 术语 | 标识 / 位置 | 说明 |
|------|-----------|------|
| **在线引擎** | `crates/regzero-wasm` | 编译为 WebAssembly 在浏览器 Web Worker 内运行，零安装支撑第 1~2 章与在线沙盒 |
| **本地桥接服务** | `crates/regzero-bridge` | 本地 Rust HTTP + WebSocket 守护进程（默认 `127.0.0.1:17320`），提供环境体检、单文件监听、C 工程构建/测试、存档同步与可选静态前端托管 |
| **项目清单** | `regzero.project.json` | 放置于玩家本地 C 项目根目录的配置文件，声明构建命令、可执行文件路径与监听目录 |
| **阶段参数** | `--stage <lex\|parse\|sema\|codegen>` | 玩家编译器 CLI 约定参数，使同一个本地 C 工程可贯穿多章不同阶段的关卡判定 |
| **统一引擎客户端** | `EngineClient`（`web/src/engine/`） | 前端统一抽象接口，屏蔽 `OnlineWasmClient` 与 `LocalBridgeClient` 的底层差异 |

## 五、关卡与判定

| 术语 | 标识 | 说明 |
|------|------|------|
| **单关目录** | `content/levels/cN_M/` | 包含 `meta.json`、`lesson.md`、`tests.json`、初始代码（在线关）与参考解 |
| **3 级提示** | `hints`（Level 1 / 2 / 3） | 按需展开的分级提示：思路图解 → 步骤拆解 → 关键代码片段 |
| **判定类型** | `goal.type` | `static` / `output` / `draw_sim` / `compile_and_run` / `scripted` |
| **关卡自检** | `regzero-core::selfcheck` | 用每关参考解跑通该关全部测例，确保关卡确定可解 |
| **一致性检查** | `every_level_page_and_test_config_are_consistent` | 校验关卡元信息、初始代码、编辑器只读/提示行号与沙盘配置合法性 |

## 六、标识符命名约定

| 场景 | 约定 | 示例 |
|------|------|------|
| 关卡 ID | `{章}-{关}` | `"1-1"`、`"4-9"` |
| 关卡目录名 | `c{章}_{关}`（**不补零**） | `c3_7` |
| 寄存器名 | `x0`..`x31` 或标准 ABI 名 | `"x3"`、`"sp"` |
| REST / WS JSON 字段 | `camelCase` | `"goalSummary"`、`"pauseKind"` |
| 存档 Key（浏览器） | `nmc:<category>:<id>` | `"regzero.progress.v1"`、`"nmc:draft:1-1"` |
