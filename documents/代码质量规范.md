# 代码质量与可维护性规范

> 本文档是 Neo Magic Compiler（Rust 引擎 + Web 前端）的**强制工程约束**。所有新增模块与重构代码必须遵守以下边界，防止项目随着章节、沙盘与本地桥接功能的扩展演变为难以维护的大泥球。

---

## 1. 分层架构与单向依赖红线

### 1.1 Rust 后端依赖方向（严禁反向或跨层耦合）

```text
riscv-simulator   (纯 RV32IM 模拟器，零 OS/IO 依赖，天然兼容 wasm32)
       ↑
riscv-assembler   (纯汇编器 + source_map + 白名单校验)
       ↑
   starlang       (C 子集编译器 → RISC-V 汇编 + 行号映射)
       ↑
 neomagic-core    (领域层：关卡加载/嵌入、DAG 解锁、Runner、Judge、DrawVM、共享 DTO)
       ↑
  ┌────┴────────┐
nmc-wasm    nmc-bridge   (薄适配层：只做协议编解码、Worker/HTTP/WS 桥接与本地进程调度)
```

- **红线 1**：`riscv-simulator`、`riscv-assembler`、`starlang` 禁止引入平台特定 IO、网络或时间依赖，确保随时可编入 `wasm32-unknown-unknown`。
- **红线 2**：`nmc-wasm` 与 `nmc-bridge` 严禁复制粘贴领域逻辑（运行、判定、解锁、DTO 定义），全部下沉到 `neomagic-core`。
- **红线 3**：所有跨边界传输结构体（DTO）统一收口在 `neomagic-core::dto`，使用 `#[serde(rename_all = "camelCase")]`，并由契约单元测试守护。

### 1.2 Web 前端依赖方向（严禁 UI 与底层引擎纠缠）

```text
src/engine/types.ts       (纯 TypeScript 契约类型，与 neomagic-core::dto 严格对齐)
       ↑
src/engine/               (EngineClient 接口、OnlineWasmClient、未来 LocalBridgeClient、progressStorage)
       ↑
src/domain/               (纯函数业务逻辑：DAG 解锁计算、寄存器格式化、约束校验 —— 零 React 依赖，可单测)
       ↑
src/sandboxes/            (数据驱动沙盘：每套沙盘拆分为 model.ts 纯状态机 + 渲染组件，经 registry.ts 注册)
       ↑
src/components/           (无页面耦合的通用工作台组件，如 PlaygroundWorkspace、CodeEditor、RegPanel)
       ↑
src/pages/ & src/app/     (页面编排与路由，不写底层解析/模拟算法)
```

- **红线 1**：React 组件（`pages/`、`components/`、`sandboxes/`）严禁直接操作 `Worker` 实例或直接读写裸 `localStorage` 键，必须经过 `EngineClient` / `progressStorage`。
- **红线 2**：沙盘核心状态流转（拖拽动作校验、指令录制、目标达成判断、防错守卫）必须写成**零 React 依赖的纯函数 reducer / model**，以便用 Vitest 直接做高覆盖单元测试。

## 2. 数据驱动铁律（严禁硬编码关卡特判）

随着关卡数量从 8 关增长到 50+ 关，最致命的腐化来源是在代码里写 `if (levelId === "1-3")`。

- **严禁在任何前端组件、沙盘逻辑或后端运行器中按 `levelId` 写特判分支**。
- 所有关卡差异（启用的沙盘类型 `sandbox.type`、单关独立的界面/部件可见性 `meta.ui`、沙盘模块 `modules[]`、允许运算符、常量卡、防错守卫 `guards[]`、寄存器角色标签、编辑器只读行、提示、测例）必须显式声明在 `content/levels/cN_M/meta.json` 与 `tests.json` 中。
- **单关 UI 配置零跨关继承**：关卡级界面开关由该关自身的 `meta.ui` 独立解析（缺省为 `false`），禁止隐式继承前置关卡的 `concepts[]`，确保单关可独立调整且天然支持未来玩家自制关卡。
- 当新关卡确实需要全新交互能力时，必须先扩展 `meta.json` Schema 并抽象为**可复用模块或守卫规则**，再实现对应插件，禁止打一次性补丁。

## 3. 可扩展性设计约束（为 7 章与 4 套沙盘预留边界）

1. **沙盘注册表（`SandboxRegistry`）**：`LevelPage` 只通过 `sandbox.type` 从注册表获取沙盘组件，后续新增 `memory-canvas`、`lexer-ast-lab`、`pipeline-stage` 时无需修改关卡页框架。
2. **沙盘内部模块化**：`manual-cpu` 采用「共享状态内核 + 可插拔 `modules[]`」设计，Phase 1 实现 `regs`/`constants`/`alu`/`pcTrack`，后续增补 `memory`/`stack`/`mmio` 时只需挂新子面板与动作处理器，不重构状态主干。
3. **DAG 技能树解锁**：关卡进度统一基于 `prerequisites: string[]` 与 `kind: "lesson" | "practice" | "challenge"` 计算，天然支持支线挑战不阻塞主线、多前置汇合与「自由探索开关」。
4. **双执行后端解耦**：前端所有功能只面向 `EngineClient` 抽象接口编程，在线 `nmc-wasm` 与本地 `nmc-bridge` 切换时，编辑器、调试器、4 套沙盘与 Diff 面板 100% 复用。

### 3.1 可视化沙盘与动画通用工程规范（适用于全部 4 套沙盘）

后续构建 `memory-canvas`、`lexer-ast-lab`、`pipeline-stage` 与扩展 `manual-cpu` 时必须共同遵守：

1. **零布局抖动（Zero Layout Shift）**：动画播放期间严禁条件挂载/卸载会改变父容器高度或宽度的 DOM 节点；总线通道、可选端口与状态槽位必须固定占位，临时浮标一律采用 `position: absolute` 悬浮。
2. **单一时间源与倍速同步**：JS 阶段调度定时器、CSS 关键帧时长与 SVG 动效必须从同一个纯函数时间轴配置派生，并随播放倍速等比例缩放，严禁在各组件里各写一套硬编码毫秒数。
3. **视觉因果同步（禁止提前穿帮）**：任何数值写入、旧值替换动效、指针/PC 变更及编辑器高亮行切换，必须在对应数据动画**抵达目标的瞬间**触发，禁止在动画刚开始时就提前把最终结果瞬移展示出来。

## 4. 模块规模、代码风格与类型安全

### 4.1 规模控制（防大泥球）
- 单个 TS/TSX 文件目标控制在 **≤ 300 行**；超过 **400 行**必须拆分（将纯计算拆到 `*.ts` / `model.ts`，将子区块拆为独立子组件）。
- 单个函数尽量聚焦单一职责（目标 ≤ 60 行），避免深层嵌套（优先早返回 early return）。
- 同类逻辑出现第 3 次时必须抽取为共享 helper 或配置项，禁止复制粘贴。

### 4.2 TypeScript 严苛模式
- `tsconfig.json` 必须开启 `strict: true`、`noUnusedLocals: true`、`noUnusedParameters: true`、`noFallthroughCasesInSwitch: true`。
- **禁止使用 `any`**；面对外部不可信 JSON 时使用 `unknown` + 类型守卫，并写明注释。
- 使用判别联合类型（Discriminated Union）表达状态机与动作（如沙盘配置、调试状态、工作模式）。

### 4.3 Rust 健壮性
- 生产代码路径禁止随意使用 `.unwrap()` / `.expect()`（仅允许在测试或已通过注释证明不可能失败的极少数不变量处使用），统一返回带中文清晰提示的 `Result`。
- 公开结构体、枚举与函数必须附带**简洁中文文档注释**（`///`），解释“为什么这么设计”而不仅是重复函数名。
- 所有文本文件必须使用 **UTF-8（无 BOM）+ LF 换行**；严禁重新引入剧情/魔法包装词汇到 UI 与工程代码中。

## 5. 自动化质量门禁（提交前必跑）

任何代码合并到 `main` 前，必须保证以下检查全部通过：

### Rust 门禁
1. `cargo test --workspace`（全仓单元与集成测试）
2. `cargo test -p neomagic-core selfcheck -- --nocapture`（全部关卡参考解自检）
3. `cargo test -p neomagic-core every_level_is_consistent`（关卡元数据、编辑约束与测例一致性校验）
4. `cargo clippy --workspace --all-targets`（保持零严重告警）

### Web 前端门禁（在 `web/` 下执行）
1. `npm run typecheck`（`tsc --noEmit` 零类型错误）
2. `npm run lint`（ESLint 零错误）
3. `npm run test`（Vitest 纯逻辑单测：DAG 解锁、沙盘 reducer、指令录制、编辑器约束）
4. `npm run build`（Vite 生产构建无报错）

### 提交卫生
- 每次 `git commit` 前必须检查 `git status --short`，严禁提交临时探针文件、`target/`、`node_modules/` 或未确认的构建垃圾。
- 每完成一个 Phase 或关键架构调整，必须同步更新 [`documents/交接文档.md`](交接文档.md)。
