# 目标与形态（`no_story` 分支总规划）

> 本文是 `no_story` 分支的**最高设计总纲（已拍板定稿）**，确立游戏的核心教学体验、强游戏化交互体系、网页与本地联动形态、1~6 章结构及分阶段路线图。
> 与旧文档冲突时，以本文与 [`架构.md`](架构.md) 为准。

## 一、产品定位与核心目标

### 1.1 我们要做一个什么样的游戏

**目标受众**：对汇编与编译原理完全零基础但有好奇心的玩家，以及希望通过亲手构建真实工程彻底吃透编译器的学习者。

**核心体验目标**：

- **玩着学会（强游戏化交互）**：编译原理和底层硬件对人类来说过于抽象，不能只靠文字和被动动画灌输。必须让玩家先在可玩沙盘里**亲手操作机制**，再写代码把手工过程自动化。
- **走得顺（平滑爬坡）**：单关只引入一个新概念；第 2 章把写编译器所需的 C 语言工具打扎实；第 3 章用极简栈式绘图机热身；第 4~6 章按「纯核心 → 功能扩展 → 高级扩展」逐步拉升，杜绝断崖式难度。
- **有爽感（高频可见反馈）**：从拖拽数字看着 ALU 运转、亲眼看到自己写的翻译器在画布上画出几何图案，到用自己的编译器跑通真实 C 程序，每一步都有强烈成就感。
- **真本事（本地真实工程）**：最终玩家在自己本地 IDE 里拥有一套可维护、可扩展、能真正编译出 RISC-V 汇编的 C 语言编译器项目。

### 1.2 `no_story` 分支原则

- **暂时完全移除剧情与魔法名词**，直接使用准确、可迁移的真实计算机术语（CPU、寄存器、内存、栈、汇编、C 语言、Token、AST、编译器），配以直观的视觉隐喻。
- 关卡数据与文本结构化分离，未来若恢复剧情，可作为独立叙事层无痛叠加。

## 二、强游戏化交互与零基础闭环设计

### 2.1 单关四步认知闭环（Micro Loop）

每一关遵循「**看目标 → 先手玩 → 写代码 → 看反馈**」四步闭环：

| 步骤 | 玩家体验 | 设计目的 |
|------|---------|---------|
| **1. 一句话目标卡（Before → After）** | 顶部固定卡片直观展示「初始状态 / 输入」与「目标状态 / 期望输出」 | 5 秒内明白本关任务，不从长文里找需求 |
| **2. 强交互沙盘手玩（Play Before Code）** | 先在可交互沙盘中亲手完成 1~2 轮手工解谜（拖数字、连指针、切 Token、拼 AST 树） | 用“动手玩”代替“看教程”，先建立肌肉记忆与直觉 |
| **3. 脚手架动手编码（Automate It）** | 系统把刚才的手工操作对应到代码概念；玩家在右侧 Playground（或本地 IDE）写代码自动化实现 | 降低面对空白编辑器的恐惧，聚焦当前唯一新概念 |
| **4. 可视化运行与多维反馈（Feedback）** | 实时播放执行动画 / 绘图结果 / 流水线点亮；失败时高亮 Diff 并支持「一键把失败测例装入调试器回放」 | 把报错变成探索线索，持续给予正面激励 |

### 2.2 四套核心可玩机制沙盘（强游戏化且工程可控）

为了既实现**强游戏化交互**、又不至于给 50+ 关每关手写一次性动画导致开发量失控，全游戏抽象为 **4 套高度可复用、数据驱动的可玩沙盘引擎**：

| 沙盘名称 | 适用章节 | 玩家怎么“手玩”（核心交互） | 如何衔接写代码 |
|---------|---------|--------------------------|-------------|
| **沙盘 1：「手动当 CPU」桌面** | 第 1 章（汇编） | 玩家亲手拖拽寄存器进「输入」与「存入」槽完成运算、往内存格塞数据、手动压栈保存返回地址 | **语义回显 + 同色语法骨架（防抄袭）**：沙盘只回显中文操作步骤，并以与槽位同色的抽象格式卡（如 `add` `[存入]`(绿), `[输入 1]`(青), `[输入 2]`(青)）呈现语序规律，**不直接吐出答案源码**，促使玩家主动把目标翻译成真实指令 |
| **沙盘 2：「内存画布 + 预测挑战」** | 第 2 章（C 语言） | 在 2D 内存画布上拖拽指针箭头、展开结构体内存偏移、连线搭建链表/树；穿插“执行第 N 行后点击会变化的格子”互动预测题 | **三联高亮**：C 代码行、内存画布节点、生成的 RISC-V 汇编实时联动，彻底打通高级语言与底层内存 |
| **沙盘 3：「切词传送带 & AST 积木台」** | 第 3~4 章前半 | 字符在传送带上滑过，玩家手动切分并贴上 Token 标签；再把 Token 卡片拖拽拼装成语法树（直观感受 `*` 比 `+` 先结合），点击播放看着树后序遍历吐出指令 | 1 分钟彻底玩懂词法分析与语法树，再回到本地 IDE 用 C 写出自动化的 Lexer / Parser |
| **沙盘 4：「实时产线与可视化终端」** | 第 3~6 章后端 | 顶部为通电式编译器流水线（`Lexer → Parser → AST → Sema → Codegen → Run`）；底部为可视化输出台（第 3 章为 **DrawVM 实时画布**，第 4~6 章为 RISC-V 执行监视器与终端） | 本地 IDE 一保存代码，网页产线自动流转点亮，画图或跑出结果，错误精确定位到阶段与行号 |

### 2.3 平滑难度曲线与兜底机制

- **锯齿形节奏**：每 3~4 个单一概念关配 1 个有趣的阶段小综合关，学完即有“原来能干大事”的爽感，下一阶段起点再微降难度引入新概念。
- **3 级按需提示（Hints）**：Level 1 思路图解 → Level 2 步骤拆解 → Level 3 关键代码片段，防止零基础卡死。
- **侧滑概念图鉴（Wiki）**：RV32IM 指令表、C 语法速查、常用数据结构（动态数组、链表、树、哈希表）模板统一放在 Wiki 中按需查阅，关卡本身保持轻盈。
- **温和的进度引导**：默认按顺序通关解锁下一关；设置中提供「自由探索开关」，有基础的玩家可随时自由跳关或进入独立 Playground。

## 三、独立 Playground 与本地联动设计

Playground（`/playground`）是贯穿全游戏的核心工作台，既可嵌入每个关卡页右侧，也可全屏独立打开，统一支持**三种工作模式**：

| 模式 | 适用场景 | 写代码位置 | 执行后端 |
|------|---------|-----------|---------|
| **在线编辑模式** | 第 1~2 章默认、随时做小实验 | 网页内置编辑器（CodeMirror 6） | 浏览器内置 `nmc-wasm`（零安装） |
| **本地单文件模式** | 第 1~2 章喜欢用本地 IDE 的玩家 | 本地 IDE 编辑单个 `.s` / `.c` 文件 | `nmc-bridge` 监听文件保存，自动同步并在网页运行与动画回放 |
| **本地 C 工程模式** | **第 3~6 章主力模式** | 本地 IDE 维护完整多文件 C 项目 | `nmc-bridge` 识别 `nmc.project.json`，调用本机 `gcc`/`clang`/`make` 构建、运行并推回可视化判定 |

**工具链与上手策略（已定）**：
- 本机 C 工具链采用**「清晰安装指引 + `nmc-bridge` 启动自动体检」**（自动检测 `gcc`/`clang`/`make` 可用性与版本，缺项直接给出一步到位的安装指引），并在 `nmc.project.json` 中保留编译器路径可配置项。
- 前端同时支持**线上静态站点访问**与 **`nmc-bridge` 本地一体托管**（访问 `http://127.0.0.1:17320`）。

## 四、六章学习路线与能力衔接（已定）

详细的语言规格、指令集与关卡表见 [`总设计.md`](总设计.md)。关键设计原则：**第 2 章学习的 C 语言范围明确大于第 4 章编译器的源语言范围**（因为玩家要用第 2 章学到的 C 工具去开发第 3~6 章的编译器），并将编译器按复杂度拆分为 4、5、6 多章逐步推进：

| 章 | 主题 | 核心目标与边界 |
|----|------|--------------|
| **第 1 章** | RISC-V 汇编入门 | 依托「手动当 CPU」沙盘，零基础掌握寄存器、内存、分支、循环、栈帧、函数调用与 MMIO |
| **第 2 章** | C 语言与编译器开发基础 | 依托「内存画布 + C↔汇编三联对照」，掌握完整 C 基础及写编译器必备的指针、字符串、结构体、递归、动态数组/链表/树/符号表 |
| **第 3 章** | 迷你编译器：绘图脚本 → `DrawVM` | 正式切入本地 C 工程；把极简绘图脚本编译成 **12 指令栈式绘图机（`DrawVM`）**指令流，在网页画布实时画出几何与分形图案，零负担走通词法 → AST → 代码生成闭环 |
| **第 4 章** | 核心编译器：C 核心子集 → RISC-V | **纯核心编译器**（`int`、算术/逻辑表达式、局部/全局变量、`if/else`、`while`、函数定义与递归，单文件汇编输出），跑通真实端到端 `compile_and_run` |
| **第 5 章** | 编译器功能扩展 | 在第 4 章同一份本地 C 工程上持续扩展：一维数组、指针与取址解引用、字符与字符串、`struct`、位运算、`for/break/continue` 及可选多文件/链接模块 |
| **第 6 章** | 高级扩展（暂不定） | 预留扩展章节：可选多级 IR 与编译优化（常量折叠、寄存器分配、死代码消除 + 周期评分榜），或进一步扩展高级语言特性 |

## 五、分阶段实施路线图

| 阶段 | 核心交付 | 闭环验收标准 |
|------|---------|------------|
| **Phase 1：Web 地基 + WASM + 沙盘 1 样板** | 搭建 `web/`（React + Tailwind + CodeMirror 6）与 `crates/nmc-wasm`；完成独立 Playground（在线模式）与**沙盘 1「手动当 CPU」**；重构第 1 章前 5 关样板 | 零安装打开浏览器，能通过「先手玩再写代码」玩通第 1 章前 5 关，支持单步/倒退与存档 |
| **Phase 2：前两章全面游戏化 + 本地单文件联动** | 完成**沙盘 2「内存画布 + 预测挑战」**与 C↔汇编对照；迁移重构第 1~2 章全部关卡并上线侧滑 Wiki；实现 `nmc-bridge` 基础版（体检 + 静态托管 + 单文件监听） | 零基础玩家可流畅通关第 1~2 章（在线或连本地 IDE 均可），全部关卡通过 `selfcheck` |
| **Phase 3：第 3 章 `DrawVM` 与本地 C 工程闭环** | 补全 `nmc-bridge` 完整 C 工程构建/监听/沙箱运行；实现**沙盘 3「切词传送带 & AST 积木台」**与**沙盘 4（`DrawVM` 绘图画布）**；落地第 3 章模板与全关卡 | 玩家在本地 VS Code 写 C 翻译器，保存即自动构建并在网页画布画出目标图形，通关第 3 章 |
| **Phase 4：第 4 章核心 C→RISC-V 编译器** | 实现编译器流水线仪表盘与端到端 `compile_and_run` 调试回放；落地第 4 章纯核心编译器模板、全关卡与参考 C 编译器自检 | 玩家用本地 C 工程逐关完成核心编译器，最终编译递归/算法程序并在网页 RISC-V 模拟器中跑通 |
| **Phase 5：第 5 章功能扩展 & 第 6 章规划** | 在第 4 章工程上扩展数组/指针/字符串/结构体等第 5 章关卡，并根据试玩反馈敲定第 6 章方向 | 玩家编译器进化为实用子集编译器，全仓测试与自检全绿 |
