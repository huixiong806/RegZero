# 关卡设计规范

> 本文档面向**关卡设计者、教学策划与 AI 出题人**，沉淀让零基础玩家**玩得顺手、不卡关、有顿悟感**的设计原则。
> 如果你已经想好关卡玩法、需要查具体的 JSON 字段与文件格式，请阅读 [`关卡编写规范.md`](关卡编写规范.md)。

---

## 1. 零基础认知负荷控制

1. **单关单概念，绝不塞入本关用不到的知识**
   - 每个概念关（`lesson`）只引入 1 个核心新概念；本关用不到的指令、寄存器或语法（例如在普通 `addi` 关里用不到的 `zero` 寄存器）**绝不提前介绍**，留到真正需要它的关卡再解锁。
2. **严禁超前编程术语**
   - 玩家默认零编程基础。在尚未教学高级语言之前（尤其是第 1 章汇编阶段），禁止在引导卡片、任务说明、提示与图鉴中出现未学概念，例如 `if / else`、`while`、`for 循环`、`指针`、`变量`、`函数`、`ALU`、`IMM`、`ASM`、`WASM` 等。
   - 统一使用直白中文或已在本关介绍过的真实计算机名词（如「走不同路线」「跳过另一条路线」「反复回到开头」「立即数」「存入」）。
3. **未用到的硬件部件彻底不渲染**
   - 早期关卡不出现内存监视器、「访存」模块、5 阶段微架构状态灯带、`x0–x31` 硬件编号、`ecall` 收尾行或系统默认的 `sp=0xF000`。
   - 每一关通过独立的 `meta.ui` 显式声明本关需要显示的界面与 CPU 部件，**不从前置关卡隐式继承**（例如禁用立即数的挑战关应直接关闭立即数端口，也方便未来玩家自制关卡）。

## 2. 教学闭环与防剧透

1. **按关卡阶段选择最顺手的破冰方式**
   - **入门破冰关（如 `1-1`、`1-2`）**：优先「先动手试算，再写指令」，让玩家用 30 秒亲手拖拽操作建立直观肌肉记忆，再写下第一条代码。
   - **概念已熟悉的中后段关卡（如 `1-3` 起）**：左侧手动试算变为**可选**，不强迫玩家先手玩通关才能写代码，避免老手或重复刷关时觉得繁琐。
   - **控制流 / 易踩坑新机制（如 `1-6` 分支跳转）**：可以直接在**右侧真实编辑器**里预置一段**带经典 Bug 的初始代码**（如写好标签但故意漏掉 `j done`），让玩家先直接点运行，盯着左侧动画亲眼看到“没刹车穿透覆盖结果”，再动手补上缺失的那一行——比大段文字定义更有顿悟感。
2. **保留思考台阶，严禁无脑抄答案**
   - 左侧手玩沙盘**不直接吐出可复制的标准答案汇编**，只展示中文操作语义 + 同色抽象语法骨架（例如 `add [存入], [输入 1], [输入 2]`）。
   - 编辑器中不放完整答案占位符；写反源/目的顺序等常见失误依靠清晰的测例 Diff 与真实执行动画让玩家自己发现，不额外保姆式剧透，保证后续章节的难度衔接。
3. **正文克制，引导分层**
   - 首次进关弹出 2~3 页简短口语化的 `briefing` 引导卡片（每页 1~2 句话），点明「遇到什么问题 → 用什么新工具 → 本关目标」，关闭后自然收进右上角「规则」按钮并可随时重播。
   - `lesson.md` 控制在 150~300 字以内，只写本关目标与核心规则；系统速查表统一放 `content/wiki/` 并随进度渐进解锁。
   - 3 级 `hints` 严格分层：Level 1 给思路方向，Level 2 给步骤拆解，Level 3 才给参考代码片段，禁止写“再想想”类空话。

## 3. 关卡节奏与测例编排

1. **三类节点交错推进**
   - `lesson`（概念关）：引入新概念；
   - `practice`（巩固关）：零新指令、零新语法，每 2~3 个概念关后穿插 1 关用于消化组合（如 `1-4` 组合算式、`1-7` 用已有跳转悟出循环）；
   - `challenge`（硬核支线）：挂在主线旁、**不阻塞主线解锁**，给学有余力的玩家提供高思维密度挑战（如 `1-4S` 原地交换、`1-7S` 更相减损 GCD），可设 `parInstructions` 鼓励精简指令。
2. **测例 1 优先命中教学痛点**
   - 尤其是带 Bug 初始代码的关卡，**测例 1 必须能立刻触发目标 Bug**（例如 `1-6` 把会触发穿透覆盖的 `12 与 5` 放在测例 1，把走跳转分支的 `4 与 9` 放在测例 2），确保玩家默认直接运行或单步测例 1 就能看到预期现象。
3. **测例精准不误杀**
   - 每关至少准备典型值 + 边界值（如 `0`、相等、负数等）。
   - 判题 `expected` 只校验与任务目标相关的寄存器或内存，不限制玩家使用了哪个空闲临时寄存器或哪种等价实现。

## 4. 动画与交互手感原则

1. **默认慢速可跟读，同时提供极速档**
   - 新手看第一次动画时，速度必须慢到肉眼能清楚追踪“哪个数从哪出来、算成了什么、写到了哪里”；同时必须提供足够快的加速档（如 `16x`）让循环关卡可以流畅冲过，并提供单步/倒退随时细看。
2. **本关目标常驻可见**
   - 顶部通栏始终展示「初始状态 → 目标结果」，无论玩家正在动手试算、写代码还是看执行动画，都不需要切回抽屉翻看题目。
3. **所见即所得的物理直觉**
   - 数值变更、覆盖写旧值被顶飞、条件跳转更新 PC 等关键事件，都要在视觉上直观呈现“为什么变成这样”，让玩家不用猜黑盒内部发生了什么。
