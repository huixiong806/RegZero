# 补码双面

## 1. 为什么 `-1` 是 `0xFFFFFFFF`？（补码）

想象一个只有 32 位的里程表：全 `0` 往前倒退 1 格就是全 `1`（`0xFFFFFFFF`）；全 `1` 再加 `1` 就会溢出绕回全 `0`。

计算机直接把「绕回前的数字」规定为负数：
- `-1` = `0xFFFFFFFF`（32 个 `1`），`-2` = `0xFFFFFFFE`
- 最高位（第 31 位）为 `1` 代表负数，为 `0` 代表非负数；
- 妙处在于：**`add` 与 `sub` 完全不用区分正负**，同一套加法电路天然成立！

## 2. 同一串比特，两种读法

点击寄存器顶栏的 **`DEC | U32 | HEX | BIN`**，可以看到同一个值在不同解读下的样子：

| 32 位十六进制 | 有符号（`DEC`） | 无符号（`U32`） |
| --- | --- | --- |
| `0x00000005` | `5` | `5` |
| `0xFFFFFFFF` | `-1` | `4294967295` |
| `0xFFFFFFF0` | `-16` | `4294967280` |

## 3. 新指令：`srai`、`bltu`、`bgeu`

| 指令 | 含义与区别 |
| --- | --- |
| `srai 目标, 源, 位数` | **算术右移**：高位复制符号位（负数补 `1`，`-16` 右移 2 位得 `-4`） |
| `bltu 左, 右, 目标` | **无符号小于**跳转（把两数当作 `0 ~ 4294967295` 比较） |
| `bgeu 左, 右, 目标` | **无符号大于等于**跳转 |

## 本关任务

给定 `t0` 和 `t1`：
1. `t2` = `t0` **算术右移 2 位**的结果；
2. `t3` = `t0` 与 `t1` 按**无符号 32 位整数**比较的较大者。
